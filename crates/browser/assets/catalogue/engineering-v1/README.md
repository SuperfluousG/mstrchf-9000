# Frozen engineering catalogue v1

These five canonical `RecipeRevision` bodies were exported on 12 October 2026 through the existing browser `initialize`/`board` API and canonicalised/hashed by the real Rust contracts. Every original ID, revision, recipe digest and byte of canonical recipe content is retained. They are synthetic engineering declarations, including their synthetic review/portion premises; freezing them supplies no real food, cooking, source or distribution authority.

Catalogue manifest material is `{"schema_version":1,"revision":"1","entries":[...]}`. Its canonical SHA-256 is `1a48cedfb36fd00affbc21615dac3d80219aa5d235385d4ce23ec0297c8b0512`. Each legacy packet digest binds `{"schema_version":1,"status":"legacy_engineering_v1","recipe":<exact recipe>}`. The loader checks exact canonical bytes, all references and packet digests, and the fixed manifest digest.

The browser build projects the native planner's catalogue onto these exact five bodies. `food-premises-v1.rs` captures the previous native adapter's synthetic evidence-pin statement, component classes, production/reuse phases, resource premises and essential-ingredient rule. It contains no arithmetic engine; the same core still performs recipe assessment, selection, scaling, scheduling and food derivation. Its SHA-256 is `f1520b18aaa63c7ec3fef4fae0ed012ef67531fb3f05a7cd8d990a1d5b446718`. The browser verifies this fixed digest before serving its catalogue or reading receipt food caches.

The copied `engineering-placeholder.png` retains the exact native asset bytes and SHA-256 `ea763c6667d13d84e962dfc3e08ea3c75f9f29cb3543543156e4065d1957b9a0`, used by recipes 4 and 5. Recipes 1–3 retain their original synthetic fixture image declarations; this capture does not convert them into verified real-food imagery or rights evidence. The synthetic evidence constructor's previous image-digest premises are preserved as engineering assumptions, not promoted into actual source or cooking observations.

New browser receipts carry `food_catalogue_pin`; omitted legacy pins explicitly resolve this same view. The full trusted pin is checked before any original-food cache lookup and is included in the cache key. Original command and Snapshot response digests remain unchanged. Unknown catalogues, substituted packet digests and a self-consistent non-admitted declaration manifest cannot reinterpret these receipts. No catalogue/admission field is added to BrowserState, and the newly declared admission command remains refused by this browser slice.

The explicit non-admitted manifest parser accepts neither a legacy/admitted status nor incoming EvidenceBasis. It preserves imported capability/review claims as data and constructs no core ReviewedRecipe or food authority. Only the compiled, separately hash-checked legacy engineering fixture supplies the legacy synthetic core premises.

Normal verification is `cargo test --manifest-path crates/browser/Cargo.toml --release --locked --offline --test catalogue`. `node crates/browser/tests/frozen-catalogue-wasm.mjs` separately checks all five frozen bodies against the current, unchanged zero-import WASM module.
